# AMOS reference candidate inspection

This pass identifies candidate media for the
[reference installation plan](../../platforms/commodore-amiga/amos/reference-profiles.md).
No new environment was booted, installed or language-tested. Product/version
labels in the candidate list remain metadata claims.

## Read-only method

Select 16 ADF payloads spanning Creator, Easy AMOS, Pro and the two compiler
lines. Read each supplied archive without modifying it, check archive CRC and
compare uncompressed payload size, CRC and SHA-1 with the corresponding supplied
catalogue entry. Record SHA-256 for stronger identity. The catalogue itself is
hashed; a match establishes agreement with that record, not provenance or
permission to redistribute the software. This is a bounded selection, not a
completeness check over every distribution or all library holdings.

Use `build198x-adf manifest` from source
`f7016398deb1fff9dc1efb6713dfab8c7bacf2d0`, binary hash recorded in
[candidate-media.json](candidate-media.json). Read its `verification` object:
process exit zero does **not** mean the filesystem passed. Reconstruct file bytes
from the reported logical ranges (OFS payload starts 24 bytes into each block),
check declared sizes and hash them. Retain selected component hashes according
to the explicit selection rule in the JSON. Non-selected files are omitted from
that public record, not assumed absent.

The manifests use CLI 0.2.12 and format library 0.3.2. No dependency was added,
source media changed, emulator session started or native program distributed.
Every temporary manifest invocation was bounded to 30 seconds and exited.

## Outcomes

- All 16 selected payloads agree with catalogue size/CRC/SHA-1 and archive CRC.
- Two filesystem results are sound: Easy 1.01 Master Disc 1 and Compiler 1.0.
- Fourteen filesystem results are rejected. Exact diagnostics remain with each
  candidate; most concern out-of-range free bitmap bits. Creator 1.34 also has
  a rejected bitmap-valid flag. These are checker results, not boot observations.
- Easy's first master disk contains installation material and split payloads.
  Its filesystem result does not establish an installed Easy runtime.
- The Pro 2.00 candidate has 77 file hashes equal to the previously executed
  distribution; only `s/Startup-Sequence` differs. Disk identity and complete
  startup qualification must therefore remain separate.
- The already-executed Pro distribution's reconstructed disk retains all 78
  original file paths, sizes and hashes, and passes the filesystem check. The
  source disk's recorded diagnostic remains visible.

Do not automatically repair rejected candidates. Investigate whether the
historical metadata convention and checker agree before choosing a read-only
boot route or an explicitly reconstructed working volume. A bitmap diagnostic
is neither a language failure nor proof that an image cannot boot.

## Ownership findings

The [ownership recommendation](../../platforms/commodore-amiga/amos/parser-ownership-options.md)
is nonbinding. Existing BASIC conversion/linting already supplies related demand;
its decision explicitly leaves parser/LSP ownership open. Asm198x's compiler
infrastructure direction anticipates future frontends but does not select a
higher-level language frontend. The proposal compares those records with a
dedicated language-tooling sibling and a temporary curriculum implementation.
No sibling charter was changed and no new repository was created.

## Verification

Recompute original/working media and file hashes independently from both raw
manifests, require a non-empty matching set of 78 files, and compare the second
Pro distribution's full file inventory before selecting public component hashes.
The supplied catalogue comparisons use independent size/CRC/SHA-1 expectations,
not values generated by the ADF manifest. Read every non-sound result and retain
its diagnostic rather than trusting exit codes. Record the 16-candidate and 2/14
result counts in `verification.json` and bind public records with artifact hashes.
JSON, local links, public-path constraints, prose and diff checks run before
commit. These are media/research checks, not parser conformance or learner tests.
