# Learner tasks: sequence and submitted text

Use the Basics overview and units 1, 2 and 5. You can trace on paper; the
pseudocode is not a program to paste into a particular machine. Keep the assessor
notes separate. A helper should record observations without coaching.

1. Predict what SHOW "Put your shoes on" changes. Distinguish the screen output
   from the action described by the words. Explain one valid instruction that
   could still express the wrong intention.
2. Trace the original three SHOW lines and the version with the first two swapped.
   Which output stays in the same position? If the last line seems missing,
   suggest an observation that could separate a stopped run from scrolled output.
3. In the greeting, predict what happens after typing Ada but before Enter.
   Then predict what happens after Enter. Which step stores the answer for SHOW?
4. Run the paper model twice with Ada. Then use empty text, three spaces,
   space-Ada-space and the text 42. Record the exact submitted text, its length
   and the greeting, marking spaces with visible boxes on your own worksheet.
   Do not treat those boxes as characters the program prints.
5. Diagnose a greeting that says Hello,Ada. Which space belongs to the program,
   and which characters belong to the input? Does accepting digits mean that
   the program converted them to a number or checked a sensible name?
6. Change the greeting to include a final exclamation mark. Predict its outputs
   for Ada and empty text, including all spaces. Trace before and after submission.
7. Create a two-line conversation that asks for some text and uses it in a
   response. State how submission works, whether empty text is accepted and
   whether spaces are retained. Check a normal, repeated and boundary answer.

Optional: follow the two Spectrum lesson links and identify the target's own
PRINT/INPUT notation. Keep those syntax rules separate from SHOW/ASK. Running
that target program is a separate observation, not a required earlier course.

Record the learner's words, errors, revisions and requested hints. Leave unaided
completion, timing, retention and transfer unknown until observed.
