# System design material

[Project purpose and direction](../PROJECT.md) and the current [curriculum guidance](../specifications/curriculum.md) govern this work. This directory contains existing game briefs, outlines, implementation notes and hardware framing. They are evidence to inspect, not a second source of project-wide policy.

Retain useful mechanics, technical investigations, prototype results and concrete build stages. During re-specification, replace old commercial benchmarks, fixed lesson counts, assumed prerequisites and historical launch cuts with an explicit agreed scope. Do not discard an existing implementation because an earlier plan used obsolete wording.

Read authored lessons, sample sources and website catalogues alongside each brief. Name whether a claim is proposed, specified, built, executed or verified on a particular emulator/hardware configuration. Reconcile conflicts explicitly. Catalogues, not prose trackers, own current inventory.

Begin with the [Spectrum review](sinclair-zx-spectrum/curriculum-review.md). The other system tracks keep their own strengths and independent entry points. Their retained design notes will need the same focused review in turn, rather than receiving a bulk Spectrum-derived rewrite.
